# Monad testnet deployment — chain 10143

> **Three fund-stranding bugs were found by deploying and then trying to use it. All three
> are fixed; all three were invisible to the local test suite.**
>
> **3. Verifiers went stale after a routine circuit rebuild — found on the first real
> deposit.** `make circuits` was run to fix the stale-committee-key bug (below), which
> regenerates every zkey with fresh contribution entropy — that non-determinism is
> deliberate, see `circuits/scripts/build.sh`. The consequence: the four verifier
> contracts baked against the OLD zkeys were still what `0x6af21cA1…` pointed at, so every
> proof built from the rebuilt circuits failed `InvalidProof()` on that pool. Confirmed by
> comparing on-chain bytecode against `forge inspect ...deployedBytecode` for all four
> verifiers — all four mismatched, sha256-different. **`0x6af21cA1…` is dead. Use
> `0x5Ede6585Ed62745E9b1a6b2F0c2Dd2e1ff5798a6`.** No test catches this because the contract
> suite builds circuits and contracts together in the same run and never checks a *previously
> deployed* verifier against a freshly rebuilt zkey — which is exactly the gap between "make
> circuits" and "redeploy." Also found and fixed in the same pass: `testnet-deploy` and
> `verify-deployment` called plain `forge` instead of `$(FORGE)` (the Monad-patched binary),
> so `--network monad` was rejected outright — the deploy could not have been re-run through
> the Makefile at all until this was fixed.
>
> **2. Wrong committee key — found at settlement.** `Deploy.s.sol` hardcoded a committee key
> copied from `circuits/build/committee-key.json`. That file is regenerated by `make keygen`,
> so the copy went stale and every deployment bound its market to a key nobody holds the
> secret for. `publishFinalTotals` requires a Chaum-Pedersen proof that the decryption share
> matches the committee key, so **the market could never settle, and a market that cannot
> settle cannot pay out.** It surfaced as `InvalidDecryptionProof()` on a real testnet
> settlement attempt — not in any test. Deploy now READS the key, with
> `COMMITTEE_KEY_X`/`_Y` env overrides for a ceremony key, and
> `test_deploy_committeeKeyMatchesTheArtifact` asserts the deployed key against the artifact
> rather than against another constant. Verified to fail on the stale key.
>
> **1. The first deployment below (`0x8Ea2…4464`) is a ONE-WAY VAULT and must not be used.**
> `Deploy.s.sol` never called `bindEncryptedTotals`, so `encryptedTotals`,
> `redeemPrivateVerifier` and `withdrawVerifier` are all `address(0)` on chain. Collateral can
> be deposited and bet, and nothing can ever be paid out — `redeemPrivate` and `withdraw` both
> revert on a zero verifier, and the public `redeem()` was removed. Fixed in `Deploy.s.sol`,
> with `test_deploy_exitPathIsWired` added to catch it; that test was verified to FAIL when the
> bind call is removed. Superseded by `0x874F…6d54`.

### Local `forge` understates real cost by 32-55%

It charges neither calldata, the intrinsic transaction cost, nor true cross-contract cold
access, and these actions cross five contracts. **Every local figure in this repo is a lower
bound.** Projections made from local numbers were wrong in the unsafe direction: `withdraw`
was projected at ~1,642,000 and came in at 1,804,341.

### Monad bills the DECLARED gas limit -- measured, not assumed

A 21,000-gas self-transfer declared at 2,000,000 was charged for **2,114,412 gas**
(0.2157 MON at ~110 gwei). This is the premise the whole uniform-envelope design rests on,
and it holds. Two consequences:

- A per-action limit would fingerprint which private action was taken, which is why every
  action declares the same one.
- The envelope is a direct tax on every action. Raising it costs users real money.

### The envelope moved once, from 2,000,000 to 2,500,000

2,000,000 was picked before anything had been broadcast. At that value the binding action
(`betEncrypted`, 1,904,445) had 95,555 gas of headroom -- and two `betEncrypted` calls in the
same run measured 1,904,445 and 1,859,711, a **44,734 spread from cold/warm variation
alone**. Roughly half the headroom was consumed by ordinary variance before any code change.

That margin is not survivable, because overrunning is worse than merely expensive: the
transaction reverts out of gas **and** the user still pays the full declared limit, so they
lose the fee and receive nothing.

At 2,500,000 the binding action sits at 76% with 595,555 of headroom, about 13x the observed
variance. It costs users roughly 0.275 MON per action against 0.220 -- the price of the
uniformity property, paid on every action.

**It should not move again.** Every change is publicly observable and shrinks the anonymity
set of everything submitted before it.

### `betEncrypted` is structurally the binding action

Local breakdown of 1,352,833: `ecpairing` 905,000 (67%), eight `ecmul` at 30,000 each for the
eight public signals (18%), `accumulateAffine` 103,684, nullifier read+write 29,196. **85% is
Groth16 verification**, and the pairing is irreducible -- it is Monad's 5x repricing of
`225,000 + 170,000k` at k=4. Hashing the four ciphertext signals into one would save 90,900 in
the verifier and cost 86,940 in Poseidon: a wash, now confirmed by measurement rather than
asserted. There is no meaningful optimisation available without changing proof system.

## Reproducing

```bash
cp contracts/.env.example contracts/.env   # add a throwaway PRIVATE_KEY
make testnet-preflight                     # checks the key is set and funded
make testnet-deploy                        # broadcasts

POOL=0x8Ea29D5C3eed4Bc6D8E68c25065f6E30BDE74464 \
COLLATERAL=0x9872b13257E958c2F7E4DcCc3F96b3C70c8e050c \
  forge script script/ExerciseEncrypted.s.sol \
    --rpc-url monad_testnet --network monad --broadcast --slow
```

The exercise replays recorded fixture proofs, so it only works against a pool whose tree is at
the genesis root. Re-running it against an already-exercised pool will fail on `UnknownRoot`.
